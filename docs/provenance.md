# Provenance

The methods in ning-stack are adapted from the upstream skills below and restated in this skill's own files; the upstream files are not shipped or loaded at runtime. Read this file when updating the stack, auditing what was kept, or answering where a method came from.

Dispositions: **Adopted** (the method's core is kept), **Partial** (selected parts kept, the rest excluded with a reason), **Conditional** (kept, loaded only under its trigger). Locations are relative to `references/` unless they start with `SKILL.md` or `scripts/`. All three source collections are MIT licensed; their notices are in `LICENSES/`.

Source links follow each project's `main` branch. The methods in this stack are maintained locally; upstream changes are reviewed before adoption. pstack playbooks live under `pstack/skills/poteto-mode/playbooks/`.

## Not adopted

- Cursor-specific mechanics: model slugs, `subagent_type` values, `pstack-models.mdc` role lines, cloud workers, transcript directory layouts, and plugin skills such as unslop, deslop, control-ui and Comment Sicko.
- Matt's `/setup-matt-pocock-skills` configuration and triage label vocabulary; the project's own tracker conventions supply those facts.
- tstack's `pr-wait` script and Monitor-based waiting; ning-stack waits on harness events and never runs polling loops or watcher agents.
- Default fan-outs: two parallel review sub-agents per round, seven why investigators, three reflect reviewers, mandatory arena for implementation. Each became a single-agent default with a conditional escalation.
- Upstream entries marked `disable-model-invocation` are neither invoked nor read at runtime; their methods are restated here with attribution.

## Simplified delivery path

The entrypoint, delivery, evidence, and review methods consolidate repeated rules. Delivery owns risk classes and the finish gate; Evidence owns test decisions, evidence levels, and reuse; Review owns severity and round limits. Existing task artifacts carry the frame and proof. Separate ledgers are conditional on findings, and the decomposition checklist applies only when splitting work. These are local adaptations, not upstream defaults. Source attribution lives in `docs/` and is not runtime guidance.

## Portable methods and executable checks

Design, continuity, and investigation now use compact decision criteria instead of fixed report structures, hypothesis counts, or repeated transition instructions. Trails remain conditional; inherited proof is reused only when its assumptions hold. T3-specific PR registration, delegation calls, and preview instructions belong to the project or harness rather than the portable methods. The GitHub gate helper checks observable remote state; it does not establish review quality, acceptance, or authorization.

Further local adaptations: the helper rejects conflicts, uncalculated mergeability, and GitHub change requests in both snapshots. Review remains mandatory for semantic instruction and procedure changes; meaning-preserving spelling, formatting, and link repairs may skip it only when project/user rules permit. Cleanup reuses an agreed maintenance baseline, and delivery closeout routes debt, changed premises, and process friction back to cleanup, optimization, and learning without authorizing extra work.

Adapted from [How the Claude Code team does code review](https://claude.dev/blog/solving-code-review-at-anthropic/) (Addy Osmani, Morgan Westlee Lunt, and Qing Wang): review findings name triggers, impact, evidence and their relation to the patch; existing project review guidance is loaded conditionally; recovery guidance covers detection and residual effects where risk warrants it. The gate now makes its limited remote-state scope visible in successful output. Multi-agent voting, scheduled whole-repo reviews, and reduced human approval requirements were not adopted.
